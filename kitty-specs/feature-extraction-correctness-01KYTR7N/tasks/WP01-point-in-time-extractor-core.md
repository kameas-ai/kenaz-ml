# WP01 — Point-in-Time Extractor Core

## Objective

Make `src/sigil_ml/features.py` the single, point-in-time-correct definition of every feature. Three changes, applied together because they interlock:

1. Every extractor accepts an explicit reference time (`as_of_ms`), defaulting to `None` meaning current wall clock.
2. Events later than the reference time are excluded before any aggregation.
3. The store-backed extractors stop reimplementing arithmetic and become thin delegates over the data-backed ones.

## Context

Elapsed-time features are currently computed against `time.time()`. That is correct when the subject is an active task, and wrong when the same function is replayed over completed tasks during training — a task that finished three months ago reports `time_in_phase_sec` of three months. Two of six stuck features currently measure recency instead of behavior.

Separately, `extract_stuck_features(store, task_id)` and `extract_stuck_features_from_data(task, events)` are parallel implementations whose docstrings promise identical output with nothing enforcing it.

Read before starting: [spec.md](../spec.md) §Context, [plan.md](../plan.md) §Implementation Shape, [research.md](../research.md) D-001 through D-004, [data-model.md](../data-model.md).

**Design decisions already made — do not relitigate:**

- **D-001**: filter in Python inside the extractors. Do **not** add an `until` parameter to `DataStore` or touch `store_sqlite.py` / `store_postgres.py`.
- **D-002**: `as_of_ms` is keyword-only, default `None`.
- **D-004**: clamp negative durations at zero; do not raise.

## Subtasks

### T001 — Add `_elapsed_sec()` clamp helper

**Purpose**: One place where FR-004 holds, so no elapsed computation can produce a negative duration.

**Steps**:

1. Add a module-private helper near the top of `features.py`, after the imports and before the first extractor:

```python
def _elapsed_sec(now_ms: int, since_ms: int) -> float:
    """Seconds between two epoch-ms timestamps, clamped at zero.

    Clock skew across event sources and out-of-order ingestion can put
    `since_ms` after `now_ms`. A negative duration is meaningless to every
    consuming model, so absorb it here rather than at each call site.
    """
    return max(0.0, (now_ms - since_ms) / 1000.0)
```

**Files**: `src/sigil_ml/features.py`

**Validation**:
- [ ] `_elapsed_sec(1000, 0) == 1.0`
- [ ] `_elapsed_sec(0, 1000) == 0.0`
- [ ] `_elapsed_sec(1000, 1000) == 0.0`

### T002 — Add `_resolve_now_ms()` and `_events_at_or_before()` helpers

**Purpose**: Centralize reference-time resolution and the no-lookahead filter (FR-003) so every extractor applies them identically.

**Steps**:

1. Add both helpers alongside `_elapsed_sec()`:

```python
def _resolve_now_ms(as_of_ms: int | None) -> int:
    """Reference time for a feature vector; None means current wall clock."""
    return as_of_ms if as_of_ms is not None else int(time.time() * 1000)


def _events_at_or_before(events: list[dict], now_ms: int) -> list[dict]:
    """Drop events after the reference time. Boundary is inclusive."""
    return [e for e in events if e.get("ts", 0) <= now_ms]
```

2. Note the inclusive boundary: an event with `ts == now_ms` is **retained**. This is specified behavior, not an off-by-one.

3. Events missing a `ts` key default to `0` and are therefore retained, matching existing tolerance for malformed rows elsewhere in this module.

**Files**: `src/sigil_ml/features.py`

**Validation**:
- [ ] `_resolve_now_ms(None)` returns approximately current epoch ms
- [ ] `_resolve_now_ms(12345) == 12345`
- [ ] An event at exactly `now_ms` survives the filter
- [ ] An event one millisecond later does not

### T003 — Thread `as_of_ms` through `extract_stuck_features_from_data`

**Purpose**: This is the function with the defect. It becomes the authoritative definition of the stuck feature vector.

**Steps**:

1. Change the signature to add a keyword-only parameter:

```python
def extract_stuck_features_from_data(
    task: dict[str, Any],
    events: list[dict[str, Any]],
    *,
    as_of_ms: int | None = None,
) -> dict[str, float]:
```

2. Replace the wall-clock line at the top of the body:

```python
now_ms = _resolve_now_ms(as_of_ms)
events = _events_at_or_before(events, now_ms)
```

3. Route **both** elapsed computations through `_elapsed_sec()`:
   - `time_in_phase_sec` — currently `(now_ms - phase_start) / 1000.0`
   - `time_since_last_commit_sec` — currently `(now_ms - last_commit_ts) / 1000.0`

4. Leave everything else alone. `session_length_sec` derives from `last_active - started_at` (both historical) and is already correct; `edit_velocity` and `file_switch_rate` are window-relative ratios. Do not "improve" them.

5. Preserve the existing fallback: when no commit events exist, `time_since_last_commit_sec` falls back to `session_length_sec`.

**Files**: `src/sigil_ml/features.py`

**Validation**:
- [ ] With `as_of_ms=None`, output matches pre-change behavior for a given fixed clock
- [ ] With `as_of_ms` set to a task's `completed_at`, elapsed features reflect that moment
- [ ] Events after `as_of_ms` do not affect `edit_velocity`, `file_switch_rate`, or the commit fallback
- [ ] Feature keys and count are unchanged (6 keys)

**Edge cases**:
- `as_of_ms` earlier than `phase_start` → `time_in_phase_sec == 0.0`, not negative
- All events filtered out → existing empty-window behavior applies unchanged
- No `phase_change` event → `phase_start` falls back to `started_at`, as today

### T007 — Reduce `extract_stuck_features` to fetch-and-delegate

**Purpose**: FR-005 and FR-006 — one definition of the arithmetic.

**Steps**:

1. Replace the entire body with fetch-and-delegate:

```python
def extract_stuck_features(
    store: DataStore,
    task_id: str,
    *,
    as_of_ms: int | None = None,
) -> dict[str, float]:
    task = store.get_task_by_id(task_id)
    if task is None:
        return _empty_stuck_features()
    return extract_stuck_features_from_data(
        task, store.get_events_for_task(task_id), as_of_ms=as_of_ms
    )
```

2. **Delete** the duplicated arithmetic. Do not leave it behind a flag or a comment.

3. Verify no behavior was unique to this path. The two implementations differ subtly today — the store-backed version keys commit detection off `kind == "git"` while the data-backed version uses `kind == "commit"`. **Resolve this deliberately**: check which kinds actually appear in the `events` table and pick the correct one. Record the choice in the WP completion notes; it changes feature values either way, and reviewers must see it called out rather than buried.

**Files**: `src/sigil_ml/features.py`

**Validation**:
- [ ] Missing task returns the empty vector without raising
- [ ] Both forms return identical dictionaries for the same task and `as_of_ms`
- [ ] No feature arithmetic remains in this function

## Risks

| Risk | Mitigation |
|---|---|
| Empty-vector values drift during T006 | Diff key-by-key against the originals before and after |
| The `git` vs `commit` kind discrepancy silently changes values | T007 requires an explicit, documented decision |
| Serving behavior changes accidentally | `as_of_ms=None` must reproduce current behavior exactly; WP04 verifies independently |
| Over-reach into adjacent cleanups | Feature definitions are frozen — change *when* they evaluate, never *what* they compute |

## Reviewer Guidance

Focus on:

1. **The empty-vector helpers.** Compare against the pre-change literals key by key. This is where a silent corruption would hide.
2. **The commit-kind resolution.** Confirm the choice was made deliberately and recorded, not defaulted by whichever implementation was copied.
3. **Filter placement.** Every aggregation must run on the filtered list. Look for any loop over the original `events` after filtering.
4. **Clamp coverage.** Every subtraction producing a duration goes through `_elapsed_sec()`.
5. **Blast radius.** `git diff --stat` should show `src/sigil_ml/features.py` and nothing else.
