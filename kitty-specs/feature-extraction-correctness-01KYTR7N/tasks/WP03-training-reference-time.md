# WP03 — Training Reference-Time Wiring

## Objective

Both trainers resolve each completed task's own reference time and pass it to the extractors. Tasks that cannot supply an honest reference time are excluded from training rather than extracted against wall clock.

## Context

This is where the defect actually bites. `trainer.py` iterates completed tasks and calls the extractors with no reference time, so every historical example is measured against today. `cloud_trainer.py` does the same through the `_from_data` variants.

Read before starting: [research.md](../research.md) D-003, [spec.md](../spec.md) FR-007/FR-008/FR-012.

**Design decision already made:** reference time resolves `completed_at` → `last_active` → skip the example. Do not fall back to wall clock; that is the bug. Do not fall back to the last event timestamp; it silently redefines what the row means depending on data completeness.

## Subtasks

### T016 — Add `_reference_time_for()` resolver

**Purpose**: One resolution rule, shared by both trainers, so local and cloud cannot drift.

**Steps**:

1. Add a module-private helper. Place it where both trainers can import it — `trainer.py` is acceptable if `cloud_trainer.py` imports from it, but a small shared location is cleaner if one already exists in `training/`.

```python
def _reference_time_for(task: dict) -> int | None:
    """Epoch ms describing the moment a completed task's features should
    reflect. None means the task cannot yield an honest reference time and
    must be excluded from training.
    """
    for field in ("completed_at", "last_active"):
        value = task.get(field)
        if value:
            return int(value)
    return None
```

2. Treat `0` and `None` alike as absent — a zero epoch is not a real timestamp in this data.

3. Do **not** add a wall-clock fallback, even defensively.

**Files**: `src/sigil_ml/training/trainer.py` (or a shared module under `training/`)

**Validation**:
- [ ] Returns `completed_at` when present
- [ ] Falls back to `last_active` when `completed_at` is absent or zero
- [ ] Returns `None` when both are absent or zero
- [ ] No wall-clock fallback anywhere in the function

### T017 — `trainer.py` stuck path passes reference time

**Purpose**: FR-007 and FR-012 for the local stuck trainer.

**Steps**:

1. In the stuck training loop (currently around line 100), the code fetches features by `task_id` only. It now needs the task record to resolve a reference time. Fetch the task, resolve, skip if `None`:

```python
for task_id in task_ids:
    task = self.store.get_task_by_id(task_id)
    if task is None:
        continue
    as_of = _reference_time_for(task)
    if as_of is None:
        skipped += 1
        continue
    features = extract_stuck_features(self.store, task_id, as_of_ms=as_of)
    ...
```

2. Count skipped rows and log once at the end at INFO, e.g. `"stuck training: skipped %d task(s) with no resolvable reference time"`. Silent dropping is not acceptable — an operator needs to see whether the training set shrank.

3. **Do not touch the label expression.** The line computing `stuck = features["test_failure_count"] > 3 and features["time_in_phase_sec"] > 600` stays exactly as written. Its behavior will change because the feature it reads is now meaningful — that is expected and in scope. Retuning the threshold is explicitly out of scope.

4. Preserve the existing synthetic-data fallback when fewer than ten completed tasks exist. Note that the skip logic may push a borderline set below that threshold; the existing guard should be evaluated against the *usable* count, not the raw count.

**Files**: `src/sigil_ml/training/trainer.py`

**Validation**:
- [ ] Every extraction passes an explicit `as_of_ms`
- [ ] Tasks with no resolvable reference time are absent from the matrix
- [ ] Skip count logged once, not per row
- [ ] Label expression byte-identical to before
- [ ] Synthetic fallback threshold evaluated against usable count
