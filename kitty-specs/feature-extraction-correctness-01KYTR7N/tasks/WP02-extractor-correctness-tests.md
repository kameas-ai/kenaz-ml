# WP02 — Extractor Correctness Test Suite

## Objective

Prove the properties WP01 claims. Every test in this package must **fail against the pre-WP01 implementation** and pass after it — a test that passes both ways is not testing the fix.

## Context

The defect being guarded against is subtle and silent: features that look plausible but encode recency instead of behavior. There is no exception, no log line, and no type error. Only a determinism assertion catches it.

## Subtasks

### T009 — Frozen-clock and fake-store fixtures

**Purpose**: Determinism tests are meaningless unless wall clock actually differs between the two extractions. A test that calls the extractor twice in the same millisecond passes trivially against the buggy code.

**Steps**:

1. Add a context manager that pins `time.time()` as seen by `features.py`:

```python
@contextlib.contextmanager
def frozen_clock(epoch_ms: int):
    """Pin wall clock as observed by sigil_ml.features."""
    with mock.patch("sigil_ml.features.time.time", return_value=epoch_ms / 1000.0):
        yield
```

2. Add a minimal fake implementing only the `DataStore` methods the extractors call — `get_task_by_id` and `get_events_for_task`. Do not subclass or import the real stores; this WP must not depend on SQLite or Postgres.

3. Add a task/event fixture builder with a known timeline. Suggested shape:

```python
T0 = 1_700_000_000_000          # arbitrary fixed epoch ms
def make_task(**overrides): ...  # started_at=T0, completed_at=T0+3_600_000, ...
def make_events(): ...           # edits, a commit, a phase_change, a failing terminal event
```

**Files**: `tests/test_features.py`

**Validation**:
- [ ] `frozen_clock` actually changes what the extractor observes as "now"
- [ ] The fake store satisfies every method the extractors call
- [ ] Fixtures produce a task whose events span a known, asserted window

### T010 — Determinism tests

**Purpose**: SC-001 and the two headline acceptance scenarios in User Story 1. This is the test that would have caught the bug.

**Steps**:

1. Extract with an explicit `as_of_ms` under one frozen clock; extract again under a clock advanced by 90 days; assert the vectors are equal.

```python
def test_extraction_is_independent_of_wall_clock():
    task, events = make_task(), make_events()
    ref = task["completed_at"]

    with frozen_clock(ref + 60_000):
        a = extract_stuck_features_from_data(task, events, as_of_ms=ref)
    with frozen_clock(ref + 90 * 86_400_000):
        b = extract_stuck_features_from_data(task, events, as_of_ms=ref)

    assert a == b
```

2. Add the positive assertion too — that elapsed features reflect the *reference* moment, not merely that they are stable:

```python
    assert a["time_in_phase_sec"] == pytest.approx(expected_phase_duration, abs=1.0)
```

Stability alone would be satisfied by a function returning constants; the value assertion is what proves correctness.

3. Repeat for the duration family.

**Files**: `tests/test_features.py`

**Validation**:
- [ ] Test fails against pre-WP01 code — confirm by stashing WP01 or by reasoning explicitly in a comment
- [ ] Both stability and absolute-value assertions present
- [ ] Covers stuck and duration families

### T011 — No-lookahead and inclusive-boundary tests

**Purpose**: FR-003 and User Story 1 scenario 3.

**Steps**:

1. Equivalence form — passing the full list with a reference time must equal passing a pre-filtered list:

```python
def test_events_after_reference_time_do_not_contribute():
    task, events = make_task(), make_events()
    ref = task["started_at"] + 600_000
    past = [e for e in events if e["ts"] <= ref]

    assert (extract_stuck_features_from_data(task, events, as_of_ms=ref)
            == extract_stuck_features_from_data(task, past, as_of_ms=ref))
```

2. Boundary form — an event at exactly `ts == as_of_ms` is **included**. Construct two event lists differing only by that one event and assert the vectors differ.

3. Assert the filter reaches the aggregates that matter: `edit_velocity`, `file_switch_rate`, `total_edits`, and the commit-recency fallback.

**Files**: `tests/test_features.py`

**Validation**:
- [ ] Equivalence test present for both families
- [ ] Inclusive boundary asserted explicitly, not implied
- [ ] At least one aggregate proven to change when a post-reference event is added

### T013 — Path-equivalence tests

**Purpose**: FR-006, SC-004, User Story 3. Guards the delegation refactor.

**Steps**:

1. For each family, call both forms with the same task and reference time through the fake store and assert exact dictionary equality:

```python
def test_store_backed_matches_data_backed():
    task, events = make_task(), make_events()
    store = FakeStore(task=task, events=events)
    ref = task["completed_at"]

    assert (extract_stuck_features(store, "task-1", as_of_ms=ref)
            == extract_stuck_features_from_data(task, events, as_of_ms=ref))
```

2. Repeat with `as_of_ms=None` under a frozen clock.
3. Assert the missing-task path returns the empty vector without raising — including that `time_of_day_hour` in the duration family is **non-zero**, since that default is easy to flatten to `0.0` during refactoring.

**Files**: `tests/test_features.py`

**Validation**:
- [ ] Equivalence asserted for stuck and duration, with and without an explicit reference time
- [ ] Missing-task empty-vector contract asserted key by key

### T015 — Edge-case tests

**Purpose**: The remaining Edge Cases section of the spec.

**Steps**:

Cover each, one test apiece:

1. Empty event list → documented empty-window behavior, no raise
2. Task with no `phase_change` event → `phase_start` falls back to `started_at`

|---|---|

## Reviewer Guidance
