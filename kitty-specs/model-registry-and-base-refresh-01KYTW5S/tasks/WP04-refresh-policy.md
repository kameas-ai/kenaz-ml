# WP04 — Refresh Policy

## Objective

Detect that a newly shipped base model differs from the one the local model descended from, and act: rebuild from retained data when the contract matches, reset honestly when it does not, and leave the previous model servable if anything fails.

## Context

This implements the chosen policy — **re-extend**. A user running for months has a local model adapted to how they work. On upgrade, a new base arrives. Their adaptation is replayed onto it rather than discarded.

The failure mode this must not have: replaying vectors computed under one contract into a model expecting another. That is why retained sets carry a contract stamp and why a contract change forces a reset instead of a rebuild.

Rebuild is **full retraining** (D-003). Warm-start extension is a later mission — do not reach for it here.

Read first: [data-model.md](../data-model.md) §Refresh, [research.md](../research.md) D-003 and D-007, [spec.md](../spec.md) User Stories 3 and 4.

## Subtasks

### T014 — Base-version change detection

**Purpose**: FR-012.

**Steps**:

1. Create `src/sigil_ml/modelstore/registry/refresh.py`.
2. Compare the base slot manifest's `version` against the local manifest's `provenance.base_version`. Equal means nothing to do.
3. Also compare `provenance.base_sha256` against the base artifact's digest — a same-numbered but different base must be detected. Version numbers can be reused by mistake; the digest cannot.
4. **Timestamps must play no part** (D-007). `last_modified()` already exists with a docstring acknowledging it is only a proxy; do not use it or any mtime here.
5. Evaluate at startup and on demand. No scheduling — nothing changes between upgrades.
6. Handle: no base present (nothing to do), no local present (nothing to refresh, base serves directly), neither present (nothing to do).

**Files**: `src/sigil_ml/modelstore/registry/refresh.py`

**Validation**:
- [ ] Same version and digest → no action
- [ ] Different version → refresh due
- [ ] Same version, different digest → refresh due
- [ ] No timestamp used anywhere
- [ ] All three absence cases handled

### T015 — Same-contract rebuild

**Purpose**: FR-013 and User Story 3 — the behavior that makes this policy worth having.

**Steps**:

1. When the retained set's `contract_version` matches the shipped base's `feature_contract.version`, rebuild.
2. Rebuild is **full retraining** on the retained examples, seeded from the new base where the estimator supports it (D-003). Do not use `warm_start` or `partial_fit` — that optimization belongs to a later mission and would change what this package verifies.
3. Write the new local artifact and manifest with:
   - `provenance.base_version` = shipped base version
   - `provenance.base_sha256` = shipped base digest
   - `provenance.n_local_extensions` = 1
   - `training.retained_generation` = the retained set's generation
   - `training.n_samples` = examples used
4. Empty retained set → serve the new base directly, no error (User Story 3 scenario 3).
5. Log the rebuild with sample count and the base version moved from and to.

**Files**: `src/sigil_ml/modelstore/registry/refresh.py`

**Validation**:
- [ ] Rebuild triggered only on contract match
- [ ] Full retraining used, no warm-start
- [ ] Provenance fields all set correctly
- [ ] Empty retained set handled without error
- [ ] Rebuild logged with counts and versions

### T016 — Changed-contract reset

**Purpose**: FR-014 and User Story 4 — the honest failure.

**Steps**:

1. When the retained set's `contract_version` differs from the shipped base's, the vectors are not replayable. Discard them.
2. Increment the generation, so subsequently retained data is distinguishable from the discarded set.
3. Serve the shipped base unextended: `n_local_extensions` = 0, `training_source` = `base`.
4. Record `provenance.reset_reason = "contract_version_changed"` — this is what makes the reset discoverable (SC-004) rather than a silent loss of personalization.
5. Log at a level an operator will see. A user losing months of adaptation deserves more than a debug line.

**Files**: `src/sigil_ml/modelstore/registry/refresh.py`

**Validation**:
- [ ] Retained set discarded on contract mismatch
- [ ] Generation incremented
- [ ] New base served unextended
- [ ] `reset_reason` recorded in the manifest
- [ ] Logged prominently

### T017 — Atomicity and refresh tests

**Purpose**: FR-019, plus proof of both refresh paths.

**Steps**:

1. Write the rebuilt artifact and manifest to temporary paths and move them into place only after both succeed. A failure at any point must leave the previous local artifact and manifest byte-identical and servable.
2. Move artifact and manifest together — a state where they disagree is worse than no refresh at all.
3. Create `tests/test_registry_refresh.py` covering:
   - Detection: same version, different version, same version with different digest
   - **Same-contract rebuild preserving personalization**: build a local model from a known retained set, ship a new base with an unchanged contract, refresh, and assert the rebuilt model's predictions are closer to the pre-refresh local model than a bare new base is. The inequality is the assertion that matters — it proves retained data actually influenced the result rather than the new base merely being served.
   - Changed-contract reset: retained set discarded, `reset_reason` recorded, base served unextended
   - Empty retained set on refresh
   - Atomicity: inject a failure mid-rebuild, assert the previous artifact and manifest are unchanged and still served

**Files**: `src/sigil_ml/modelstore/registry/refresh.py`, `tests/test_registry_refresh.py`

## Risks

| Risk | Mitigation |
|---|---|
| Replaying stale-contract vectors into a new model | T016 resets instead; the contract stamp makes it detectable |
| Half-written refresh leaves no servable model | T017 requires temp-then-move for both files together |
| Reaching for warm-start because it seems more correct | D-003 defers it; full retraining satisfies every acceptance scenario |
| Silent personalization loss on reset | `reset_reason` plus prominent logging |
| A test that asserts refresh "worked" without proving retained data mattered | T017 requires the distance inequality |

## Reviewer Guidance

1. **The inequality test in T017 is the package.** Without it, nothing proves personalization survived — the new base being served would pass a weaker assertion.
2. **Check timestamps are absent** from detection.
3. **Kill the process mid-rebuild** and confirm the previous model still serves.
4. **Confirm no `warm_start` or `partial_fit`** appears — that is a later mission.
