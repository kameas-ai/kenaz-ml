# WP01 — Manifest and Validation Core

## Objective

Define the manifest schema, read and write it, and implement the three validation checks that stand between a model artifact and being used: integrity, feature contract, runtime compatibility. Validation returns structured results; it does not raise at callers.

## Context

Base models will be shipped and extended locally. Two failure modes arrive with them and are invisible today: deserializing a `.joblib` is arbitrary code execution, and an artifact trained against a different feature set silently produces meaningless predictions because both trainers build vectors with `features.get(f, 0.0)`.

The manifest is also the interface to the cloud side — the MLflow export job will write this exact schema (C-002), so nothing in it may assume local paths.

Read first: [data-model.md](../data-model.md) §Manifest and §Resolution, [research.md](../research.md) D-004 and D-006.

## Subtasks

### T001 — Manifest schema and JSON read/write

**Purpose**: The record every artifact carries.

**Steps**:

1. Create `src/sigil_ml/modelstore/registry/__init__.py` and `manifest.py`.
2. Model the schema in [data-model.md](../data-model.md) §Manifest — `schema_version`, `name`, `version`, `created_at`, `provenance`, `runtime`, `feature_contract`, `training`, `metrics`, `artifact_sha256`. Use dataclasses; serialize with `json` from the standard library. **No new dependencies** (C-001) — no pydantic, no jsonschema.
3. Reading a manifest must tolerate:
   - unknown fields (forward compatibility with a newer cloud exporter)
   - missing optional fields (`provenance.reset_reason`, `training.retained_generation`, `metrics`)
   - a base manifest, which omits `provenance.base_version` and `base_sha256`
4. Reading a corrupt or unparseable file returns "unusable", never raises (FR-017).
5. Writing must be deterministic — stable key order — so manifests diff cleanly.

**Files**: `src/sigil_ml/modelstore/registry/__init__.py`, `src/sigil_ml/modelstore/registry/manifest.py`

**Validation**:
- [ ] Round-trips without loss
- [ ] Unknown fields preserved or safely ignored, documented either way
- [ ] Corrupt JSON returns unusable rather than raising
- [ ] Base-shaped manifest (no `base_version`) parses
- [ ] Only stdlib imports

### T002 — Integrity verification before deserialization

**Purpose**: FR-005. The ordering is the whole point.

**Steps**:

1. Add a check computing SHA-256 over the artifact bytes and comparing against `artifact_sha256`.
2. Structure the API so it is **impossible to deserialize without having verified** — verification takes the raw bytes and returns them, or returns a refusal; it never takes an already-loaded model. A caller must not be able to skip it by convention.
3. Stream the hash in chunks rather than reading the whole artifact into memory twice.
4. Hash mismatch returns a refusal naming `integrity`, with the expected and actual digests in the detail.

**Files**: `src/sigil_ml/modelstore/registry/manifest.py`

**Validation**:
- [ ] Verification runs on bytes, before any `joblib.load`
- [ ] Mismatch returns a refusal, does not raise
- [ ] Refusal detail carries both digests
- [ ] Meets NFR-003: under 200ms for a 50MB artifact

### T003 — Ordered feature-contract validation

**Purpose**: FR-006, and the check that kills the silent-zero corruption.

**Steps**:

1. Compare `feature_contract.names` against the ordered names the local extractors produce for this model, **element by element in order** (D-006). A set comparison is wrong: it accepts a reordering that permutes every model input, which is exactly the silent failure this feature exists to prevent.
2. Compare dtypes positionally.
3. Fail closed. Any difference is a refusal.
4. The refusal detail must name the specific disagreement — missing names, extra names, or the first index at which order diverges. "Contract mismatch" alone is not enough to act on.
5. Source the expected names from the `FEATURE_NAMES` constants the trainers already index against, so validation and vector construction cannot disagree.

**Files**: `src/sigil_ml/modelstore/registry/manifest.py`

**Validation**:
- [ ] Identical ordered lists pass
- [ ] Reordered but identical *set* is **refused**
- [ ] Missing name refused, and named in the detail
- [ ] Extra name refused, and named
- [ ] Dtype mismatch refused
- [ ] Expected names derive from the same constants the trainers use

### T004 — Runtime version compatibility check

**Purpose**: FR-008. Base models are pickles shipped to installs whose runtime we do not fully control.

**Steps**:

1. Compare `runtime.sklearn_version` against the running version.
2. Define compatibility deliberately and document the rule in the docstring. A reasonable default: identical major.minor passes; differing major.minor refuses. State the choice rather than leaving it implicit.
3. Refusal detail names both versions.
4. Note in the docstring why this matters asymmetrically — the frozen bundle pins its runtime, while a source install resolves whatever satisfies the version range, which is where this check earns its keep.

**Files**: `src/sigil_ml/modelstore/registry/manifest.py`

**Validation**:
- [ ] Matching version passes
- [ ] Incompatible version refused with a diagnostic, not a deserialization traceback
- [ ] Compatibility rule documented

### T005 — Manifest and validation tests

**Purpose**: Prove all four behaviors.

**Steps**:

## Risks

| Risk | Mitigation |
|---|---|
| Set-based contract comparison silently permutes inputs | T003 and T005 both require the reordering case |
| Checksum verified after deserialization, providing no protection | T002 structures the API so verification precedes; T005 asserts it |
| A dependency creeps in for schema validation | Explicitly prohibited; stdlib only |
| Manifest assumes local filesystem semantics, breaking the cloud exporter | Schema carries no paths; C-002 is checked at review |

## Reviewer Guidance

1. **Try to skip the integrity check.** If you can construct a call that deserializes without verifying, the API shape is wrong.
2. **Check the contract comparison is ordered**, not `set(...) == set(...)`.
3. **Read the refusal details** — would an operator know what to do from them?
4. **Confirm no new dependency** appears in `pyproject.toml`.
