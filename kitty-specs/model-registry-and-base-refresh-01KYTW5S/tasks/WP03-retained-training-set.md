# WP03 — Retained Training Set

## Objective

Store the training examples behind local extensions so personalization can be replayed onto a newly shipped base model. Local, inspectable, bounded, deletable, and stamped with the contract version the vectors were computed under.

## Context

The chosen base-refresh policy is re-extend: when a new base ships, the user's adaptation is rebuilt onto it rather than discarded. That requires keeping the training data, which is new behavior for a product whose central promise is that nothing leaves the machine.

Two consequences shape this package. First, the format is JSONL rather than a compact binary one (D-002) — the user must be able to open the file and see exactly what is retained, or the local-only claim is weaker than it sounds. Second, vectors are only replayable against the contract version they were computed under, which is why every set carries that stamp and why WP04 resets on a contract change.

Read first: [research.md](../research.md) D-002, [data-model.md](../data-model.md) §Retained Training Set.

## Subtasks

### T010 — JSONL writer with header

**Purpose**: FR-009. Persist examples with the stamp that makes them replayable.

**Steps**:

1. Create `src/sigil_ml/registry/retained.py`. Write to `config.retained_data_dir() / f"{name}.jsonl"`.
2. Follow the schema in [data-model.md](../data-model.md): one header record, then one example per line with `x`, `y`, and `as_of_ms`.
3. The header carries `contract_version`, `generation`, and the ordered `names`. Duplicating names into the file makes it self-describing when read on its own — which is the point of it being inspectable.
4. Appending to an existing set must verify the header's `contract_version` matches the current contract. A mismatch is a programming error at this layer, not a data condition: WP04 owns resets. Refuse the append and say so.
5. Write with `json.dumps` per line, standard library only. No new dependencies.
6. `as_of_ms` comes from the reference time introduced by `feature-extraction-correctness` — carry it through, do not recompute it.

**Files**: `src/sigil_ml/registry/retained.py`

**Validation**:
- [ ] Header written once, on first append
- [ ] Examples append one per line
- [ ] Contract-version mismatch on append is refused
- [ ] File is human-readable — `head -2` shows a header and an example
- [ ] Only stdlib imports

### T011 — Tolerant reader

**Purpose**: A retention file is written incrementally and can be interrupted. Reading must never be the thing that breaks training.

**Steps**:

1. Read the header, then examples.
2. Tolerate, per [data-model.md](../data-model.md):
   - **Missing or unparseable header** → treat the whole set as no retained data
   - **Truncated final line** → discard that line, keep the rest
   - **Empty file** → no retained data
   - **An unparseable line mid-file** → skip it, count it, log the count once
3. Return examples plus the header metadata, so WP04 can compare `contract_version` and record `generation`.
4. Never raise to the caller. An unreadable retention file costs personalization, not availability.

**Files**: `src/sigil_ml/registry/retained.py`

**Validation**:
- [ ] Round-trips a written set
- [ ] Missing header → empty result, no raise
- [ ] Truncated final line → earlier examples survive
- [ ] Mid-file corruption → skipped and counted
- [ ] Empty file → empty result

### T012 — Bound enforcement and eviction

**Purpose**: FR-010 and NFR-004 — bounded, with a predictable policy.

**Steps**:

1. Enforce a configurable cap, defaulting to 50MB per model.
2. On exceeding it, evict oldest-first: rewrite the file retaining the newest examples that fit, preserving the header.
3. Rewrite atomically — temp file then move — so an interrupted eviction cannot destroy the set.
4. Document the policy in the module docstring. "Predictable" in FR-010 means a user can reason about what is kept without reading the code.
5. Log evictions with the number of examples dropped.

**Files**: `src/sigil_ml/registry/retained.py`

**Validation**:
- [ ] Cap configurable, 50MB default
- [ ] Newest examples survive, oldest dropped
- [ ] Header preserved after eviction
- [ ] Eviction is atomic
- [ ] Drop count logged

### T013 — Deletion, generation increment, and tests

**Purpose**: FR-018, plus the generation counter WP04 needs.

**Steps**:

1. Deletion removes the file entirely. The install must remain servable afterward — deleting retained data costs personalization and nothing else.
2. Generation increments when a set is reset, so a manifest can record which generation trained it. Since deletion removes the file, persist the generation counter in the next header written rather than in a separate file.
3. Expose a size/count summary for the discovery surface a later mission will add.
4. Create `tests/test_registry_retained.py` covering: round-trip; all four tolerance cases from T011; eviction keeping newest with a valid header; deletion followed by successful re-accumulation; generation increment across a reset.
5. Assert nothing in this module opens a socket. The full no-egress verification lives in WP06, but this is where the risk originates.

**Files**: `src/sigil_ml/registry/retained.py`, `tests/test_registry_retained.py`

**Validation**:
- [ ] Deletion leaves the install servable
- [ ] Accumulation restarts after deletion
- [ ] Generation increments across resets
- [ ] All tolerance cases covered
- [ ] No socket opened
- [ ] `pytest tests/test_registry_retained.py` passes

## Risks

| Risk | Mitigation |
|---|---|
| Retaining user-derived data weakens the privacy claim | Local-only by construction, inspectable format, deletable; verified in WP06 |
| An unreadable retention file breaks training | T011 makes every failure mode return empty rather than raise |
| Interrupted eviction destroys the set | T012 requires atomic rewrite |
| A compact binary format is chosen for size | D-002 settled this — inspectability outweighs size, and the bound is not binding at these volumes |

## Reviewer Guidance

1. **Open a retention file and read it.** If you cannot tell what is stored from the file alone, the format has failed its purpose.
2. **Grep the module for network imports.** There must be none.
3. **Interrupt an eviction** and confirm the set survives.
4. **Confirm the reader cannot raise** — every branch returns.
