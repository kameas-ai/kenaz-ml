# WP06 — Guarantee Verification

## Objective

Verify the three claims that span packages and cannot be tested inside any single one: that behavior is unchanged when no base models exist, that retained data never leaves the machine, and that provenance is answerable end to end.

## Context

Each earlier package tests its own surface. These three properties emerge from their combination, and each is a claim the product makes rather than a function it implements — the kind that goes unverified precisely because no single module owns it.

Read first: [spec.md](../spec.md) SC-006, SC-007, SC-008 and User Story 5, [quickstart.md](../quickstart.md) §1 and §8.

## Subtasks

### T022 — No-base default-state verification

**Purpose**: SC-008. **This is the most important test in the mission**, because no base models exist yet — every install in the world runs in this state today and will until the first base model is built.

**Steps**:

1. Create `tests/test_registry_guarantees.py`.
2. With an empty base slot and an empty local slot, assert:
   - Model resolution reaches existing cold-start behavior
   - Training runs and produces a model exactly as it does today
   - Prediction endpoints return what they returned before this mission
   - No error, no warning that would alarm a user, no missing-file exception
3. With an empty base slot and a *populated* local slot — the state of an install that has been training for a while — assert the local model serves normally and refresh is a no-op.
4. Capture the pre-mission behavior explicitly rather than asserting only "no exception". Absence of a crash is not evidence of unchanged behavior.

**Files**: `tests/test_registry_guarantees.py`

**Validation**:
- [ ] Empty-both state reaches cold start unchanged
- [ ] Empty-base with local present serves local, refresh is a no-op
- [ ] Assertions cover behavior, not merely absence of exceptions
- [ ] No alarming log output in the default state

### T023 — No-egress verification

**Purpose**: SC-006 and FR-011. The product's central promise is that nothing leaves the machine, and this mission is the first to persist user-derived training data.

**Steps**:

1. Assert **structurally** that no socket is opened during local training and retention — patch or monkeypatch socket creation and assert it is never called during the training path.
2. Do **not** settle for asserting that a known upload function went uncalled. The guarantee is "no egress", not "no egress through the paths we remembered to check"; a structural assertion catches a path nobody anticipated.
3. Cover the full local flow: training, retention write, eviction, manifest write, refresh.
4. Assert no configuration setting in the local deployment can enable transmission of retained data (C-003) — if a config key could plausibly do so, that is a finding to raise rather than a test to write.
5. Confirm the retained-data path stays within `config.retained_data_dir()`; assert no write escapes that directory.

**Files**: `tests/test_registry_guarantees.py`

**Validation**:
- [ ] Socket creation asserted absent, structurally
- [ ] Full local flow covered
- [ ] Writes confined to the expected directory
- [ ] No config path enables transmission

---

### T024 — End-to-end provenance verification

**Purpose**: SC-007 — the question that is unanswerable today.

**Steps**:

1. Drive a realistic lifecycle and assert provenance is correct and complete at each stage:
   - Fresh install, no models → provenance reports no model
   - Base shipped, never extended → descends from base vN, zero extensions, `training_source` = `base`
   - Extended locally three times → descends from base vN, three extensions, `training_source` = `local`
   - New base shipped, same contract, refreshed → descends from base vN+1, extension count reset per WP04, retained generation recorded
   - New base shipped, changed contract, reset → `reset_reason` recorded, zero extensions
2. At each stage assert the three questions from SC-007 are answerable: which base, how many extensions, which contract version.
3. Assert provenance and the served model never disagree — the model actually serving must be the one the manifest describes, verified via `artifact_sha256`.

**Files**: `tests/test_registry_guarantees.py`

**Validation**:
- [ ] All five lifecycle stages covered
- [ ] Three SC-007 questions answerable at each stage
- [ ] Provenance matches the served artifact by digest
- [ ] `pytest tests/test_registry_guarantees.py` passes

## Risks

| Risk | Mitigation |
|---|---|
| The no-base case treated as an edge case | T022 states plainly that it is the current production state and tests it first |
| No-egress asserted too weakly | T023 requires structural socket assertion |
| Provenance drifts from the served artifact | T024 verifies by digest, not by trusting the manifest |

## Reviewer Guidance

1. **Read T022 first.** If it does not convince you an install with no base models behaves exactly as it does today, this mission is not safe to merge.
2. **Check the egress assertion is structural.** Patching a known uploader is not sufficient.
3. **Confirm provenance is verified against the artifact digest**, not merely read from the manifest.
