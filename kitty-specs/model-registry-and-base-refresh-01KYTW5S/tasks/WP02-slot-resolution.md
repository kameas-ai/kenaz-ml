# WP02 — Slot Resolution

## Objective

Resolve two slots with different roots — a read-only base slot shipped inside the distribution and a writable local slot under `config.models_dir()` — and serve them in preference order, falling through to existing cold-start behavior when neither yields a usable artifact.

## Context

`config.models_dir()` returns `~/.local/share/sigild/ml-models`, which is user-writable because local training writes there. A shipped base model must be read-only and tamper-evident, so it cannot live in that directory. Per D-001 it ships inside the distribution and is read in place: notarization covers its integrity, upgrade replaces it for free, and version-change detection reduces to comparing manifests.

The consequence is that base and local are **not siblings** and need separate resolvers.

**Today there are no base models at all.** Every install runs with an empty base slot, and will until the first is built. That is the default case, not an edge case.

Read first: [research.md](../research.md) D-001, [data-model.md](../data-model.md) §Slot Layout and §Resolution.

## Subtasks

### T006 — `base_models_dir()` and `retained_data_dir()` resolution

**Purpose**: Give the two new locations well-defined paths across both distribution forms.

**Steps**:

1. Add `base_models_dir()` to `config.py`. It resolves differently by distribution form:
   - Frozen bundle: relative to `sys._MEIPASS`
   - Source install: package resources relative to the installed package
   Detect via `getattr(sys, "frozen", False)`, consistent with how the freeze work already distinguishes them.
2. Unlike `models_dir()`, this function **must not create the directory** — it is read-only and may legitimately not exist (no base models shipped yet). Return the path regardless; existence is the caller's question.
3. Add `retained_data_dir()` returning `models_dir() / "retained"`, created on demand like `models_dir()`.
4. Keep `models_dir()` and `weights_path()` exactly as they are — the local slot keeps its current flat layout so pre-registry artifacts are still found.

**Files**: `src/sigil_ml/config.py`

**Validation**:
- [ ] `base_models_dir()` resolves under a frozen bundle and a source install
- [ ] It does **not** create the directory
- [ ] It returns a path even when nothing is shipped
- [ ] `retained_data_dir()` created on demand
- [ ] `models_dir()` and `weights_path()` unchanged

### T007 — Two-slot resolution order

**Purpose**: FR-003 and FR-004.

**Steps**:

1. Create `src/sigil_ml/modelstore/registry/slots.py` implementing the order in [data-model.md](../data-model.md) §Resolution: local slot, then base slot, then cold start.
2. For each slot, an artifact is usable only if both the artifact and its manifest exist **and** WP01's validation passes.
3. Expose which slot answered, so provenance and diagnostics can report it.
4. The base slot is read-only: this module must expose no write path to it (FR-015, C-004). Do not add one "for tests" — tests can construct a temporary directory.

**Files**: `src/sigil_ml/modelstore/registry/slots.py`

### T008 — Unusable-artifact fallthrough

**Purpose**: FR-017 — a bad artifact degrades gracefully rather than taking predictions down.

**Steps**:

1. Every unusable condition falls through to the next step rather than raising: missing artifact, missing manifest, corrupt manifest, integrity failure, contract mismatch, runtime mismatch.
2. Log each fallthrough with the model name, the slot, and WP01's refusal reason and detail. A silent fallthrough is as bad as a silent corruption — the operator must be able to see that a model was refused and why.
3. A base-slot refusal deserves a louder level than a local-slot refusal: a bad local model self-heals on the next training run, while a bad base model means a broken release the install cannot repair.
4. Never let a refusal propagate as an exception to the prediction path.

**Files**: `src/sigil_ml/modelstore/registry/slots.py`

**Validation**:
- [ ] All six unusable conditions fall through
- [ ] Each logs model, slot, reason, detail
- [ ] Base-slot refusal logged at a higher level than local
- [ ] No exception reaches the caller

### T009 — Slot resolution tests

**Purpose**: Prove resolution, with emphasis on the state every install is actually in.

**Steps**:

1. Create `tests/test_registry_slots.py`.
2. **The no-base case first.** Empty base slot, empty local slot — assert cold-start behavior is reached and is unchanged from today. This is the current production state and the most important test here (SC-008).

6. Test the frozen-vs-source resolution branches directly by patching the frozen indicator — the packaged build is not exercised by the test suite, so a wrong path there would otherwise ship undetected.
