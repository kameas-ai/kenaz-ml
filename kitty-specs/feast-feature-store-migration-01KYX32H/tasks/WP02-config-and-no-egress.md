# WP02 — Configuration and No-Egress Guarantee

## Objective

Two configurations — local self-contained, cloud PostgreSQL — and a structural proof that the local deployment opens no network socket for any feature operation.

## Context

**This package encodes a hard product requirement.** C-001: the local install has no network path to the cloud feature store. Not a default, not a convention — a requirement.

That matters because Feast *supports* remote registries, remote online stores, and remote providers through configuration. A guarantee resting on "we didn't configure that" is one edit away from being false, and the edit would look innocuous in review.

Feast 0.65.0 has no telemetry module — verified against the installed package, and the anonymous usage collection present in older 0.x releases is gone. That makes the requirement achievable; it does not make it self-enforcing.

Read first: [research.md](../research.md) D-004, [data-model.md](../data-model.md) §Deployment configuration, [spec.md](../spec.md) User Story 2.

## Subtasks

### T005 — Local configuration

**Purpose**: FR-003, FR-004, FR-005.

**Steps**:

1. Create `feature_store.local.yaml` per [data-model.md](../data-model.md): `provider: local`, `registry_type: file` pointing at the shipped registry, `online_store: sqlite` under `~/.local/share/sigild/`.
2. **Declare no offline store.** Local training computes directly; an offline store here would be dead configuration inviting a future remote value.
3. The file must contain **no host, URL, port, credential, or endpoint of any kind**. Not commented out — absent.
4. The registry path resolves inside the bundle and is read-only (FR-013). The online store path is in the user data directory and is writable. Do not collapse these into one root.

**Files**: `src/sigil_ml/feature_store/feature_store.local.yaml`

**Validation**:
- [ ] `provider: local`, file registry, sqlite online store
- [ ] No offline store declared
- [ ] Zero network-shaped values, including in comments
- [ ] Registry path read-only; online store path writable

### T007 — Config resolution by operating mode

**Purpose**: Select the right configuration, and make the wrong one unreachable locally.

**Steps**:

1. Resolve via `config.operating_mode()`, the mechanism already used to choose between `SqliteStore` and `PostgresStore`.
2. **The local path must not be able to load the cloud configuration** (FR-004 scenario 4). Structure the resolution so that in local mode the cloud file is never read — not read-then-ignored.
3. Fail with a clear diagnostic if the mode is unrecognised; never fall back to a network-capable default.
4. Resolve the bundle registry path correctly for both distribution forms — frozen bundle (`sys._MEIPASS`) and source install — mirroring how `base_models_dir()` is expected to work.

**Files**: `src/sigil_ml/feature_store/config.py`

**Validation**:
- [ ] Mode resolution matches the existing store-selection mechanism
- [ ] Cloud config unreachable in local mode
- [ ] Unknown mode fails loudly, no network-capable default
- [ ] Registry path resolves in both distribution forms

### T008 — Structural no-egress test and config lint

**Purpose**: NFR-004 and SC-002. **The most important subtask in this package.**

**Steps**:

1. Create `tests/test_no_egress.py`.
2. Patch socket creation to record every call, run the **full local flow** — load config, read registry, push a vector, resolve features, serve a prediction — and assert the record is empty.
3. Assert *no socket at all*. Do **not** write a test that checks known upload functions went uncalled: the guarantee is "no egress," not "no egress through the paths we thought of." A structural assertion catches a path nobody anticipated, which is the entire point.
4. Add a configuration lint asserting the local YAML matches no network-shaped pattern (`http`, `://`, `host`, `port`, `password`, `token`, `endpoint`), so a future edit introducing one fails the suite.
5. Add a test that the cloud configuration is not loaded in local mode.
6. Assert the local flow completes with outbound network genuinely unavailable, not merely unused.

**Files**: `tests/test_no_egress.py`

**Validation**:
- [ ] Socket-level assertion across the full local flow
- [ ] Not an allow-list of known calls
- [ ] Config lint rejects network-shaped values
- [ ] Cloud config proven unreachable locally
- [ ] Flow succeeds with network unavailable

## Risks

| Risk | Mitigation |
|---|---|
| A future edit adds a remote value to the local config | T008's lint fails the suite |
| No-egress asserted too weakly | T008 requires socket-level assertion, explicitly not an allow-list |
| Cloud config leaks into the local path | T007 makes it unreachable; T008 asserts it |
| Feast version bump reintroduces telemetry | The socket assertion runs in CI and would catch it |

## Reviewer Guidance

1. **Read the local YAML line by line.** Any host, URL, port, or credential — even commented — fails this package.
2. **Check the egress test is structural.** If it patches a named uploader rather than socket creation, it is not sufficient.
3. **Try to load the cloud config in local mode.** If you can, T007 is not done.
4. This is a stated hard requirement from the product owner; treat weakness here as blocking rather than as a nit.
