# WP03 — Local Serving Resolver

## Objective

Active-task predictions compute features live and push the result to the online store. **The online store is never the source for an active-task prediction.**

## Context

This inverts Feast's conventional read path, deliberately (D-003).

The models answer questions about *right now* — is this developer stuck, how long will this task take. An online store returns the last materialized value, so reading it at serving time trades correctness for microseconds on the exact path where freshness is the product. Computing live and pushing keeps predictions current, still populates the store for other consumers, and makes the store a byproduct rather than a dependency.

This is precisely what the April attempt had backwards: it adopted the online half, stubbed the offline half, and ended up with a TTL'd cache in front of functions that already existed.

Read first: [research.md](../research.md) D-003, [data-model.md](../data-model.md) §Serving flow, [spec.md](../spec.md) User Story 5.

## Subtasks

### T009 — Live-compute-then-push resolver

**Purpose**: FR-014. The core of the package.

**Steps**:

1. Create `src/sigil_ml/feature_store/resolve.py` exposing a resolver for a model family and entity.
2. For an **active** task the resolver:
   - calls the existing extractor in `sigil_ml.features` with no reference time (`as_of_ms=None` → now)
   - returns that vector to the caller
   - pushes it to the online store as a side effect
3. **Never read the online store for an active task.** Structure the function so there is no code path that returns a stored value for an active entity — this is a guarantee to enforce in the shape of the code, not a convention to remember.
4. Non-active entities may read the store normally.
5. Preserve the vector exactly: same keys, same order, same values as the extractor returns. This package changes *where values go*, never what they are (C-005).

**Files**: `src/sigil_ml/feature_store/resolve.py`

**Validation**:
- [ ] Active-task resolution computes live
- [ ] No code path returns a stored value for an active task
- [ ] Vector identical to the extractor's output, ordering included
- [ ] Non-active path may read the store

### T011 — Best-effort push semantics

**Purpose**: FR-017 — a store problem must not become a prediction outage.

**Steps**:

1. The push is best-effort: a failure logs at WARNING and the prediction still returns.
2. Do not retry inline. The next cycle will push again, and blocking a prediction on store availability defeats the point of computing live.
3. Log failures with the entity and feature view, rate-limited so a persistently failing store cannot flood the log.
4. Track a simple counter for observability, so silent persistent failure is visible.
5. **Push failures must never alter the returned vector.** The caller receives the computed values regardless.

**Files**: `src/sigil_ml/feature_store/resolve.py`

**Validation**:
- [ ] Push failure does not fail the prediction
- [ ] Returned vector unaffected by push outcome
- [ ] No inline retry
- [ ] Failures logged, rate-limited, counted

### T012 — Live-not-stale serving tests

**Purpose**: Prove the central claim.

**Steps**:

1. Create `tests/test_feature_store_local.py`.
2. **The headline test**: seed the online store with a deliberately wrong value for an entity, generate live activity, request a prediction, and assert the wrong value does not appear. If this passes with the store seeded wrong, live compute genuinely won.
3. Assert the push happened — the store holds the freshly computed vector afterwards.
4. Assert a **failing** push leaves the prediction intact and the vector unchanged.
5. Assert vector identity against the extractor's direct output, ordering included.
6. Assert an empty online store on first run serves without error.
7. Measure resolution latency against NFR-002's 20% budget and record it — the sibling mission left an NFR cited but unmeasured, and that should not repeat.

**Files**: `tests/test_feature_store_local.py`

**Validation**:
- [ ] Seeded-wrong-value test present and passing
- [ ] Push verified
- [ ] Failing push covered
- [ ] Vector identity asserted
- [ ] Empty store on first run covered
