# WP02 — Stack B Coverage, Then The Move

## Objective

Give the untested model-loading path coverage, **then** move six modules into `datastore/` and `modelstore/` and rewrite every import site.

## Context

This package was originally two. Ownership validation rejected that split, correctly: the Stack B tests must be written against the *old* import paths and then carried to the new ones, so both packages needed to own the same two files. The tests and the move are one unit of work.

**The internal ordering is therefore load-bearing and is not a style preference.** T004–T007 (write the tests) must be complete and committed before T008 begins (start moving). Written after the move, the tests would only prove the code works in its new home; written before, they prove it behaves identically in both. That is the entire basis for claiming this move is behaviour-preserving (FR-005, C-001).

**Commit T004–T007 separately from T008–T013.** The commit boundary is what lets a reviewer confirm the ordering was honoured — it is the only remaining evidence, now that the package boundary is gone.

Target layout:

```
src/sigil_ml/
├── datastore/
│   ├── __init__.py     re-exports
│   ├── protocol.py     ← store.py            DataStore, create_store
│   ├── sqlite.py       ← store_sqlite.py     SqliteStore
│   └── postgres.py     ← store_postgres.py   PostgresStore
└── modelstore/
    ├── __init__.py     re-exports
    ├── stores.py       ← storage/model_store.py   ModelStore, Local, S3, Cached
    ├── loader.py       ← loader.py                ModelLoader, FilesystemModelLoader
    └── cache.py        ← cache.py                 ModelCache
```

## Part 1 — Coverage (T004–T007). Complete and commit before Part 2.

### T004 — `ModelCache` tests

**Purpose**: FR-008. Import from `sigil_ml.cache` — the **current** path.

**Steps**:

1. Create `tests/test_model_cache.py`.
2. Cover: TTL expiry (past-TTL entry reads as a miss, miss counter increments); LRU eviction (at `max_size`, least-recently-used goes); statistics (hits, misses, evictions, hit-rate arithmetic); `evict(tenant_id)` removing only that tenant's entries; `evict_all()`; `cleanup_expired()` returning its count; `loaded_tenants()` reporting only non-expired entries.
3. Patch `time.monotonic()` rather than sleeping — the cache uses it, and a test that sleeps for a TTL is slow and flaky.
4. The cache documents itself thread-safe; at minimum assert concurrent `get`/`put` does not corrupt state.

**Validation**: TTL, LRU, statistics, both eviction paths covered · `time.monotonic()` patched · passes against the current implementation

---

### T005 — `FilesystemModelLoader` tests

**Purpose**: FR-009. Import from `sigil_ml.loader`. Tenant scoping is the subtlest behaviour here.

**Steps**:

1. Create `tests/test_model_loader.py`.
2. Cover the documented resolution order — `{models_dir}/{tenant_id}/{model_name}.joblib`, then `{models_dir}/{model_name}.joblib`:
   - tenant-specific artifact wins when present
   - shared fallback applies when it is absent
   - **cross-tenant isolation** — two tenants with different artifacts under the same model name each get their own. Assert by **content**, not by path.
   - **`None` on missing** — returns `None`, does not raise. The protocol docstring states this and callers depend on it.
   - unreadable/corrupt artifact — document what the current implementation does rather than asserting what it should do.
3. Use `tmp_path`. Never touch the real `~/.local/share/sigild/`.

**Validation**: all five behaviours covered · isolation asserted by content · real user directories untouched

| Risk | Mitigation |
|---|---|
| Tests written after the move, forfeiting their purpose | Part 1 commits before Part 2; commit order is the evidence |
| A vacuous test blesses a broken move | T006 requires demonstrated failure per behaviour |
| Tidying while moving makes the diff unreviewable | T008/T009 forbid content changes; reviewer checks diff shape |
| A shim survives and hides stale imports | T012 forbids shims and asserts `ModuleNotFoundError` |
| The two caches get "helpfully" merged | C-002 forbids it |
| An assertion needs changing to pass | T013 makes that an escalation — it would mean behaviour changed |

## Reviewer Guidance

1. **Check the commit order first.** Part 1 must precede Part 2. That is now the only evidence the tests were written against the pre-move code, since the package boundary that used to enforce it is gone.
2. **Check T006 was actually run** — without demonstrated failure these tests are decoration, and they are the only safety net for this code.
3. **Read the diff shape.** Renames plus import lines. Any hunk changing logic inside a moved file is out of scope regardless of merit.
4. **Grep for shims** — a module whose whole body is a re-export.
5. **Confirm the two caches are untouched.**
