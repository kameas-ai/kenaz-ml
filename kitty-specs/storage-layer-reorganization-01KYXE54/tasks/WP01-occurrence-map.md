# WP01 — Occurrence Map

## Objective

Produce an exhaustive, reviewable inventory of every site where a moved symbol appears, covering all eight standard bulk-edit categories. **Nothing moves until this is approved** (C-006, D-006).

## Context

This mission is `change_mode: bulk_edit` — it relocates the same identifiers across many files. The occurrence map is the guardrail: it is both the plan for the rewrite and the artifact a reviewer checks the final diff against.

## Subtasks

### T001 — Enumerate occurrences across all eight categories

**Purpose**: The map itself.

**Steps**:

1. Load the `spec-kitty-bulk-edit-classification` skill and follow it — it defines the eight categories and the required shape of `occurrence_map.yaml`.
2. Every one of the eight standard categories needs an **explicit action**, including the ones that turn out empty. An absent category is indistinguishable from an overlooked one:
   - `code_symbols` · `import_paths` · `filesystem_paths` · `serialized_keys`
   - `cli_commands` · `user_facing_strings` · `tests_fixtures` · `logs_telemetry`
3. Search beyond `src/` and `tests/`. The categories most likely to be missed here are not code:
   - `CLAUDE.md` — names `src/sigil_ml/store.py` directly
   - `docs/ML_ARCHITECTURE.md` — references `src/sigil_ml/store.py`
   - `freeze/kameas-ml.spec` — `collect_submodules("sigil_ml")` plus any explicit module lists
   - `kitty-specs/**` — prior missions' specs reference these paths
   - `pyproject.toml` — packaging config
4. For each occurrence record the file, line, current text, and intended action.

**Files**: `kitty-specs/storage-layer-reorganization-01KYXE54/occurrence_map.yaml`

**Validation**:
- [ ] All eight categories present with explicit actions
- [ ] Non-code locations searched, not just `src/` and `tests/`
- [ ] Each occurrence records file, line, current text, intended action

### T002 — Confirm no moved module is string-referenced

**Purpose**: The claim that makes this safe. A statement import fails loudly when missed; a string reference fails silently at runtime.

**Steps**:

1. Search for dynamic references to the six moving modules — quoted module paths, `importlib.import_module`, `__import__`, entry points, `getattr` on module objects.
2. Planning found exactly one string-referenced module in the codebase, `sigil_ml.app:app` (uvicorn, at `cli.py:98` and in the freeze spec) — and it is **not** moving. Confirm that independently rather than taking it on trust.
3. If you find any string reference to a moving module, that is a **finding that changes the plan** — record it prominently in the map and report it. It would mean the rename has a silent-failure path the plan does not account for.

**Files**: `occurrence_map.yaml`

**Validation**:
- [ ] Dynamic-reference search performed and its method recorded
- [ ] `sigil_ml.app:app` confirmed as the only string-referenced module
- [ ] Any string reference to a moving module escalated, not just logged

### T003 — Reconcile against the measured count

**Purpose**: Make the map falsifiable.

**Steps**:

1. Count the import statements your map lists and compare to the measured 41.
2. **A discrepancy either way is informative, not a failure.** More means planning's grep missed something (record what). Fewer means planning double-counted a line matching two patterns (record which). Either way, state the reconciliation explicitly — a map that silently disagrees with the plan is worse than one that disagrees loudly.
3. Record the per-module breakdown so WP03 can check itself off against it.

**Files**: `occurrence_map.yaml`

**Validation**:
- [ ] Count compared to 41 and any difference explained
- [ ] Per-module breakdown recorded
- [ ] The map is usable as WP03's checklist
