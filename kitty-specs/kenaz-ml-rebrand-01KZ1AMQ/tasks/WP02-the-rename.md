# WP02 — The Rename

## Objective

Rename `sigil_ml` → `kenaz_ml` and `kameas-ml` → `kenaz-ml` across every site the occurrence map lists, leave every site it marks `do_not_change` untouched, and **prove both**.

## Context

1,738 `sigil_ml` occurrences across 165 files; 420 `kameas-ml` across 74. `occurrence_map.yaml` from WP01 is your checklist — work from it and tick entries off. Do not freehand a global substitution; the map exists so the rewrite is auditable, and T011 cross-checks the diff against it.

**Verification is in this package, not a separate one.** A bulk edit rewrites `tests/**`, so a verification package would have needed to own files this one must also touch — the storage reorganization was planned that way and ownership validation correctly rejected it.

### The one way this mission can do real damage

`kenaz-ml` is the ML sidecar for [`sigil`](https://github.com/wambozi/sigil), a **separate Go daemon** owning `~/.local/share/sigild/data.db`.

- **RENAME**: `sigil_ml` (this package), `kameas-ml` (this distribution and CLI)
- **NEVER**: `sigild`, `sigil` the daemon, `~/.local/share/sigild/`, `SIGILD_PLUGIN_URL`, `sigilctl`, `github.com/wambozi/sigil`, prose about "the Sigil daemon" — **138 references**

A blanket `sigil` → `kenaz` substitution would rewrite the data path. Every install would then point at a database that does not exist, **while importing perfectly** — it would look like it worked. T010 makes this an asserted invariant rather than a hope.

Read first: [plan.md](../plan.md) D-001 through D-007, [research.md](../research.md), and **`occurrence_map.yaml`**.

**Steps**:

2. Do not restructure anything. No module moves, no reorganization — the storage reorganization already settled the layout, and mixing a rename with a move makes both unreviewable.

**Validation**: `git mv` used; diff shows renames · no module moved within the package

### T010 — The two invariants

**Purpose**: FR-007 and FR-012 — the two places where *not* changing something is the correct action.

**Steps**:

1. **The Sigil surface is unchanged.** After the rename, assert by count that the 138 `sigild`/Sigil-daemon references are still present. Then assert at runtime, because text can be present and still wrong:
   ```python
   assert config.db_path() == Path.home()/".local/share/sigild/data.db"
   ```
   Add this as a **committed test**, not a one-off check. It is the invariant most worth guarding permanently.
2. **The frozen-history alias keeps its old key.** In `tests/test_migration_regression.py`, `sys.modules["sigil_ml.store"]` must stay exactly that — it matches text inside git object `ef67e05`, whose SHA256 is asserted immediately before the blob executes. Only the *value* follows the rename. Add a comment saying so, so a future reader does not "fix" it.
3. Run that test and confirm it passes.

**Validation**: Sigil-surface count asserted in a committed test · `db_path()` asserted at runtime · alias key unchanged with an explanatory comment · migration-regression test passes

2. **Check the alias key in `test_migration_regression.py` still reads `sigil_ml.store`.** It looks like a leftover and is correct.
3. **Confirm the frozen binary served a real prediction**, not merely that it built.
4. **Read the diff shape** — renames plus name substitutions. Any hunk changing logic is out of scope regardless of merit.
5. **Confirm `kitty-specs/` for merged missions is untouched.**
