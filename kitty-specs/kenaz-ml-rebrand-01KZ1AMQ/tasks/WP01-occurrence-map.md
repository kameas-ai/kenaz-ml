# WP01 — Occurrence Map

## Objective

Inventory every occurrence the rename touches, and — the part that matters most — classify every `sigil` hit as **this product** (rename) or **the Sigil daemon** (never rename). Nothing changes until this is approved (C-005).

## Context

Measured before planning: **1,738 `sigil_ml` across 165 files**, **420 `kameas-ml` across 74 files**, and **138 `sigild`/Sigil-daemon references that must not change**.

`kenaz-ml` is the ML sidecar for [`sigil`](https://github.com/wambozi/sigil), a **separate Go daemon** that owns `~/.local/share/sigild/data.db`. A blanket `sigil` → `kenaz` substitution would rewrite that data path, and every install would then point at a database that does not exist — while importing perfectly and looking like the rename had worked. Your classification is what prevents that.

Read first: [spec.md](../spec.md) §"The distinction that governs this mission", [research.md](../research.md) D-001 and §"The categories that hide from a working-tree grep", [plan.md](../plan.md).

### T002 — Classify every `sigil` hit — **the mission's core**

**Steps**:

1. Partition every occurrence of the string `sigil` into exactly two sets, with a reason recorded per entry:
   - **RENAME** — `sigil_ml`, the Python package: this product.
   - **DO NOT CHANGE** — `sigild`, `sigil` the daemon, `~/.local/share/sigild/`, `SIGILD_PLUGIN_URL`, `sigilctl`, `github.com/wambozi/sigil`, and prose describing "the Sigil daemon" or "Sigil developer intelligence".
2. **Ambiguous cases must be resolved explicitly, not defaulted.** Prose is where this bites: "the ML sidecar for Sigil" keeps *Sigil*; "kameas-ml is Sigil's ML service" renames *kameas-ml* and keeps *Sigil*. Read the sentence, decide, record why.
3. Verify the do-not-change set totals **138**. A different number is a finding: state whether the measurement was wrong or you found something new.
4. Call out any file containing **both** categories — those are where a careless edit does damage, and WP02 needs them flagged.
5. `~/.local/share/sigild/` appears in code, tests, and docs. Every instance is do-not-change. Confirm none is missed.

**Validation**: every `sigil` hit classified with a reason · 138 confirmed or the discrepancy explained · mixed-category files flagged · all data-path instances in the do-not-change set

### T003 — String-resolved and grep-invisible references

**Purpose**: These fail at *runtime*, not at collection. A statement-shaped search cannot see them.

**Steps**:

1. Enumerate the four known runtime-resolved sites and confirm each independently:
   - `"sigil_ml.app:app"` — uvicorn target in `cli.py`
   - `collect_submodules("sigil_ml")` and the `"sigil_ml.app"` hidden import — `freeze/kameas-ml.spec`
   - `kameas-ml = "sigil_ml.cli:main"` — `[project.scripts]` in `pyproject.toml`
   - the editable install's `.pth`, written from the distribution name
2. Search for others: `importlib.import_module`, `__import__`, `getattr` on modules, entry points, quoted dotted paths.
3. **Record the git-object reference explicitly.** `tests/test_migration_regression.py` runs `git show ef67e05:src/sigil_ml/features.py` and executes it; that blob contains `from sigil_ml.store import DataStore`. It is frozen — its SHA256 is asserted — so the `sys.modules` alias key **must keep the old name** while its value follows the rename (D-004). Put this in the map as a `do_not_change` with that reasoning, so a reviewer seeing `sigil_ml` there recognises it as correct rather than a leftover.
4. Check for sibling worktrees holding an old tree. All were cleaned up after the last mission; confirm rather than assume.

**Validation**: four known sites confirmed · additional dynamic-reference search performed and its method recorded · git-object alias recorded as do-not-change with reasoning · worktree check performed
